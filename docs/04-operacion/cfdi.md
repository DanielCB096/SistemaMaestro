# CFDI y facturación electrónica

**Estado:** decisión diferida; V2 no timbra.  
**Regla:** no afirmar obligaciones fiscales sin validación de un contador.

## Alcance de Tienda V2

- V2 emite ticket interno, no CFDI.
- Puede almacenar datos fiscales del emisor y del receptor para una extensión futura.
- No se anuncia como “sistema de facturación electrónica”.

## Opciones futuras

| Opción | Descripción | Riesgo |
|---|---|---|
| A | V2 solo entrega datos para que el cliente autofacture en un portal | Menor complejidad; no resuelve la facturación completa |
| B | Integración con PAC (Facturama, SW Sapien, Diverza u otro) | Costo por timbre, internet, CSD, catálogos SAT, cancelaciones |
| C | Servicio de terceros que recibe los datos y timbra | Dependencia externa y costo recurrente |

## Preguntas para el contador

- ¿Qué régimen y obligaciones aplican al cliente ideal?
- ¿Qué comprobantes debe emitir y con qué periodicidad?
- ¿Qué datos fiscales debe capturar el sistema?
- ¿Qué pasa con tickets de venta al público?
- ¿Cuál es el plazo real para timbrar y cancelar?
- ¿Qué costo por timbre y por cancelación debe presupuestarse?

## Riesgos

- Prometer CFDI sin PAC operativo.
- Requerir internet en un producto que se vende como offline.
- Almacenar certificados CSD sin la seguridad adecuada.
- Costo recurrente que el modelo de pago único no cubre.
