# Ronda de skills para los agentes — 2026-11-23

**Objeto:** definir el catálogo de skills de los agentes que trabajan el código de Tienda V2, con prioridad, contenido mínimo, criterios de aceptación y documentación auditable.  
**Participantes:** ChatGPT (producto/negocio), Claude (arquitectura/riesgo), Gemini (UX/operaciones).  
**Método:** misma decisión y mismo formato para los tres; cada uno respondió desde su rol, sin ver las respuestas de los otros.  
**Resultado:** catálogo consolidado de 13 artefactos: 6 skills P0, 4 skills P1 de ejecución, 2 documentos de contexto y 1 herramienta (graphify).

## Contexto entregado a los tres

- Tienda V2 es .NET MAUI + SQLite, offline, Windows-first, para abarrotes, purificadoras y minisúper de 1–3 cajas y 1–4 empleados.
- Plan de 90 días con hitos H1–H6.
- `SistemaMaestro` es la fuente de verdad documental; el código vive en `tienda`.
- Equipo: Daniel (dueño), DeepSeek (OpenCode/ejecución), ChatGPT (negocio), Claude (arquitectura/riesgo) y Gemini (UX/operaciones).
- Restricción: las sesiones web no cargan skills locales; las skills se instalan en OpenCode/CLI y el catálogo se documenta en el repositorio.

## Coincidencias

- **`sqlite-local`, `seguridad-permisos` y `testing-dotnet` son P0 para los tres.** Es el núcleo del riesgo: datos, permisos y regresiones.
- **`graphify` no debe ser prioridad.** Los tres lo mandan a P2: útil para explorar y para desmontar `DatabaseTools`, pero no bloquea la venta ni la integridad.
- **La lista inicial estaba sesgada a tecnología.** Faltaban respaldo, entrega en campo, hardware y reglas de dinero/caja.
- **Hay que documentar y versionar las skills.** No basta con crearlas: deben tener dueño, versión, disparadores y criterios de aceptación.
- **No instalar todo de golpe.** Primero P0; el resto cuando una tarea real lo pida.

## Reglas del catálogo

1. **Una skill = una capacidad verificable.** No se crea una skill por cada tecnología.
2. **Toda skill P0 cita al menos una prueba o un comando de verificación.**
3. **El código vive en `tienda`; el catálogo vive en `SistemaMaestro`.** Cada cambio de código debe citar la versión de la skill que usó.
4. **Las skills se versionan en Git.** Cambiar una skill P0 requiere ADR y revisión de otro rol.
5. **Las sesiones web no cargan skills.** ChatGPT, Claude y Gemini usan el catálogo como documento de contexto; solo OpenCode/CLI las cargan como instrucciones.
6. **Si una skill queda desfasada respecto al código, se corrige o se retira.** Un catálogo grande y obsoleto es peor que uno pequeño y vigente.

## Riesgos

- **[HIPÓTESIS] Un catálogo grande que nadie mantiene se vuelve ruido.** Mitigación: empezar con 6 P0 y añadir P1 solo cuando una tarea lo exija.
- **[HIPÓTESIS] Las skills de reglas (dinero, permisos) pueden quedar desfasadas.** Mitigación: cada regla debe tener una prueba que la cite.
- **[HECHO] ChatGPT llegó al límite de contexto al terminar la respuesta.** La sesión queda usable solo con resumen o chat nuevo; no se debe asumir memoria ilimitada.
- **[RECOMENDACIÓN] Verificar que OpenCode cargue cada skill** con una tarea de prueba cuya respuesta correcta dependa de la skill.
